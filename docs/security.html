امنیت و حریم خصوصی

کلیپ‌نوت هیچ سرور، حساب کاربری یا تحلیل آماری ندارد. این صفحه دقیقاً می‌گوید چه چیزی روی دستگاه شما می‌ماند، چه دسترسی‌هایی گرفته شده و قفل یادداشت تا کجا محافظت می‌کند.

اصل اول: همه‌چیز محلی است

  • یادداشت‌ها، تنظیمات، فضای کاری، دسته‌بندی و برچسب‌ها در chrome.storage.local روی همان کامپیوتر ذخیره می‌شوند.
  • هیچ همگام‌سازی ابری، آپلود یا پشتیبان‌گیری خودکار روی سرور وجود ندارد.
  • هیچ ابزار تحلیل، ردیاب یا اسکریپت خارجی بارگذاری نمی‌شود؛ حتی فونت فارسی هم داخل بسته اکستنشن است.
  • تنها درخواست شبکه‌ای که اکستنشن می‌زند، خواندن شماره نسخه از گیتهاب برای اطلاع دادن نسخه جدید است.

دسترسی‌ها و دلیل هرکدام

دسترسیبرای چه استفاده می‌شود
storageذخیره و خواندن یادداشت‌ها و تنظیمات به‌صورت محلی

clipboardReadدکمه چسباندن (Paste) در ویرایشگر

چیزی که گرفته نشده

هیچ دسترسی به تاریخچه مرور، کوکی‌ها، بوک‌مارک‌ها، تب‌های دیگر یا محتوای صفحات داده نشده است. اکستنشن هیچ اسکریپتی داخل صفحات وب تزریق نمی‌کند.

قفل یادداشت

روی هر یادداشت می‌توانید جداگانه قفل بگذارید:

  • رمز عبور (حداقل یک کاراکتر) یا پین ۴ رقمی (دقیقاً چهار رقم).
  • رمز هرگز ذخیره نمی‌شود؛ فقط هش آن با الگوریتم PBKDF2-SHA256، با ۱۵۰٬۰۰۰ تکرار و یک سالت تصادفی ۱۶ بایتی نگه داشته می‌شود.
  • سوال بازیابی اختیاری است و پاسخ آن هم با همین روش هش می‌شود، پس پاسخ هم به‌صورت متن ساده ذخیره نمی‌شود.
  • تا وقتی یادداشت باز نشده، متن و پیش‌نمایش آن مخفی است و فقط عنوان و مشخصات دیده می‌شود.
  • باز بودن یادداشت فقط برای همان نشست است و ذخیره نمی‌شود؛ با دکمه «قفل دوباره» یا بستن و باز کردن اکستنشن دوباره قفل می‌شود.
محدودیت مهم قفل — حتماً بخوانید

قفل، محتوای یادداشت را رمزنگاری نمی‌کند؛ فقط نمایش آن را در رابط کاربری می‌بندد. متن یادداشت به‌صورت متن ساده در حافظه محلی کروم می‌ماند. بنابراین قفل برای جلوگیری از دیده شدن اتفاقی یادداشت توسط کسی که پشت سیستم شما می‌نشیند مناسب است، اما در برابر کسی که به پروفایل کروم یا فایل‌های سیستم شما دسترسی کامل دارد محافظت کامل نیست. دکمه «حذف قفل» هم بدون دانستن رمز قابل استفاده است. برای داده‌های واقعاً حساس، رمزنگاری سطح سیستم‌عامل یا یک ابزار رمزنگاری اختصاصی انتخاب درست‌تری است.

فراموش کردن رمز یا پین

  1. در پنجره باز کردن یادداشت، گزینه بازیابی رمز را بزنید.
  2. سوال بازیابی نمایش داده می‌شود؛ پاسخ درست را وارد کنید تا یادداشت باز شود.
  3. اگر سوال بازیابی تنظیم نکرده باشید، راهی برای بازگرداندن رمز وجود ندارد؛ در این حالت می‌توانید قفل را از بخش حفاظت حذف کنید.

امن بودن متن و خروجی

  • پیش از نمایش هر یادداشت، متن از کاراکترهای خطرناک HTML پاک‌سازی می‌شود؛ پس تگ script داخل یادداشت اجرا نمی‌شود.
  • پیوندهای تولیدشده با rel="noopener noreferrer" و در تب جدید باز می‌شوند.
  • سیاست امنیت محتوا (CSP) اکستنشن اجازه بارگذاری اسکریپت خارجی را نمی‌دهد و ارتباط شبکه‌ای را به api.github.com و github.com محدود می‌کند.

پیشنهادها

  • از فایل clipnote-backup-*.json مثل یک فایل خصوصی نگهداری کنید؛ همه یادداشت‌ها، حتی قفل‌شده‌ها، داخل آن هستند.
  • اگر کامپیوتر مشترک است، رمز یا پین را روی یادداشت‌های حساس بگذارید و بعد از کار، زبانه مدیر را ببندید.
  • فایل پشتیبان را بعد از انتقال به کامپیوتر جدید از مسیر عمومی پاک کنید.

Security & privacy

ClipNote has no server, no account and no analytics. This page states exactly what stays on your device, which permissions are taken, and how far the note lock actually protects you.

First principle: everything is local

  • Notes, settings, workspaces, categories and tags are stored in chrome.storage.local on the same computer.
  • There is no cloud sync, no upload and no automatic server-side backup.
  • No analytics, trackers or third-party scripts are loaded — even the Persian font is bundled inside the extension.
  • The only network request the extension makes is reading the version number from GitHub to announce a new release.

Permissions and why each one exists

PermissionWhat it is used for
storageReading and writing notes and settings locally
clipboardWriteThe copy button on notes and code blocks
clipboardReadThe Paste button in the editor
activeTabReading the title and URL of the page you quick-save from
contextMenusThe Save to ClipNote item in the right-click menu
notificationsSave success/failure notices and the new-version notice
alarmsScheduling the update check, because the service worker is not always awake
api.github.com and github.comOnly fetching the published version number to compare with the installed one
What is not requested

No access to browsing history, cookies, bookmarks, other tabs or page content. The extension injects no scripts into web pages.

Note lock

Every note can be locked individually:

  • Either a password (at least one character) or a 4-digit PIN (exactly four digits).
  • The secret is never stored; only its hash is kept, using PBKDF2-SHA256 with 150,000 iterations and a random 16-byte salt.
  • The optional recovery question answer is hashed the same way, so it is not stored in plain text either.
  • Until a note is unlocked its content and preview stay hidden; only the title and metadata are visible.
  • The unlocked state lasts for the session only and is never persisted; use “relock”, or restart the extension, to close it again.
Important limitation of the lock — please read

The lock does not encrypt note content; it only hides it in the user interface. The note text remains plain text in Chrome's local storage. So the lock is well suited to stop someone who sits at your computer from casually reading a note, but it is not full protection against someone with complete access to your Chrome profile or your file system. The “Remove Lock” button can also be used without knowing the secret. For truly sensitive data, OS-level encryption or a dedicated encryption tool is the better choice.

Forgetting the password or PIN

  1. In the unlock dialog choose Recover password.
  2. The recovery question is shown; enter the correct answer to open the note.
  3. If no recovery question was set there is no way to restore the secret; in that case you can remove the lock from the Protection panel.

Safe text and output

  • Before any note is rendered its text is escaped for dangerous HTML characters, so a script tag inside a note never runs.
  • Generated links open in a new tab with rel="noopener noreferrer".
  • The extension content security policy (CSP) forbids loading external scripts and limits network connections to api.github.com and github.com.

Recommendations

  • Treat the clipnote-backup-*.json file as private: it contains every note, including locked ones.
  • On a shared computer, lock sensitive notes and close the manager tab when you are done.
  • Delete the backup file from any public location after moving to a new computer.
